# 万能战斗模拟器：属性与公式库设计规格

## 目标

把当前 1v1 工作台改为四个配置页签，使独立开发者能先定义属性和可复用公式，再定义技能并将技能挂载到角色。常规用户不需要编辑 JSON，但能看见每项属性的中文名和英文 ID，并用英文 ID 写出安全的战斗公式。

## 用户工作流

1. 在“属性配置”定义数值属性，例如“攻击力 `atk`”和“暴击率 `critRate`”。
2. 在“公式配置”定义命名公式，例如“平方伤害 `squareDamage`”的表达式 `self.atk ^ 2 / target.def ^ 2`。
3. 在“技能配置”定义“重击”，效果从公式库选择 `squareDamage`。
4. 在“角色配置”把“重击”挂载给红方、蓝方或两者，并调整同刻结算顺序。
5. 运行模拟；同一技能在不同角色上使用各自的 `self`、`target` 属性求值。

## 四页签

### 角色配置

- 编辑红方、蓝方的名称和每个已定义属性的数值。
- “已装备技能”显示全局技能库中的技能，可添加、移除和排序。
- 角色只保存技能 ID；技能定义不复制到角色内。
- 每个角色至少装备一个攻击触发技能，避免无法行动的默认配置。

### 技能配置

- 维护唯一的全局技能库：名称、触发方式和效果链。
- 技能可被任意角色重复挂载；技能本体改动会影响所有装备它的角色。
- 效果保留伤害、治疗、DOT、属性修正四种类型。
- 每个效果可以选择公式库项目；未选择时保留现有的内联高级公式作为兼容和兜底。

### 属性配置

- 每项属性定义为 `{ id, name, type: 'number', defaultValue }`。
- `id` 只能使用字母、数字和下划线，首字符必须为字母；它是公式和 JSON 的稳定英文键。
- `name` 是 UI 的中文显示名；页面同时显示 `名称 (id)`。
- `hp`、`maxHp`、`attackInterval` 是不可删除的系统属性。`hp` 和 `maxHp` 必须为正数，`attackInterval` 必须大于 0。
- `atk`、`def` 作为基础模板的普通可编辑属性保留。新增属性默认值必须是有限数字。
- 删除一个属性前，必须阻止仍被角色数值、属性修正或公式引用的删除操作。

### 公式配置

- 每项公式定义为 `{ id, name, expression }`，其中 `id` 遵循属性 ID 相同的英文规则。
- 表达式仍由现有受限解析器执行；允许数学运算、现有函数、`self`、`target`、`context` 与 `random()`，禁止 JavaScript。
- 编辑器旁显示可用属性速查：`self.攻击力 (atk)`、`target.防御力 (def)`；点击插入对应英文变量。
- 保存时进行语法与安全校验。引用不存在属性可保存但标记警告，因为属性可能在后续添加；运行前配置校验必须阻止它。

## 数据模型与兼容

当前配置升级到版本 2：

```json
{
  "version": 2,
  "attributes": [
    { "id": "hp", "name": "生命值", "type": "number", "defaultValue": 100 },
    { "id": "atk", "name": "攻击力", "type": "number", "defaultValue": 10 }
  ],
  "formulas": {
    "basicDamage": { "name": "基础伤害", "expression": "max(1, self.atk - target.def)" }
  },
  "skills": {
    "heavyStrike": {
      "name": "重击",
      "trigger": { "type": "interval", "seconds": 5 },
      "effects": [{ "type": "damage", "formulaId": "basicDamage" }]
    }
  }
}
```

`effect.formulaId` 优先引用 `formulas[formulaId].expression`。没有 `formulaId` 的旧效果继续使用其 `formula` 文本；导入版本 1 时补上 `defaultValue` 并保持旧属性、技能与公式行为不变。导出统一写版本 2，但不强制把内联公式转换成公式库项目。

## 模拟与校验

- 内核在 `runBattle` 前解析效果的有效公式：有 `formulaId` 时从公式库读取表达式，否则读取 `formula`。
- 校验公式 ID 存在、属性 ID 唯一、角色拥有所有已定义属性、技能 ID 存在、属性修正属性存在。
- 公式中的变量只能来自运行时角色属性；`self` 是施法者，`target` 是目标，`context.time` 是当前战斗时间。
- 公式库项目的表达式错误应报到 `formulas.<id>.expression`；效果引用错误应报到 `skills.<id>.effects.<n>.formulaId`。

## 范围边界

本期不增加新效果类型、资源系统、目标选择、条件分支、公式间相互引用、团队战斗或公式分享社区。公式库只保存单条受限表达式。

## 验收

- 用户能新增“暴击率 `critRate`”，两名角色都出现该属性输入。
- 用户能新增“平方伤害 `squareDamage`”，表达式为 `self.atk ^ 2 / target.def ^ 2`。
- 用户能让“重击”引用该公式，并把同一“重击”挂载给双方角色。
- 双方角色使用同一技能时，根据各自属性得到不同伤害。
- 删除仍被公式、角色或属性修正使用的属性会得到明确错误。
- 导入现有版本 1 配置后可运行；导出后为版本 2 配置。
